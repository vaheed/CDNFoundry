# CDNFoundry v0.9.8

This release brings the full accumulated `dev` work into `main`, including domain
claim and edge security corrections, origin and TLS lifecycle fixes, rebuilt
production dependencies, Fleet improvements and the latest staging work. The
release inventory was reviewed against pre-merge `main` at `602c605b`, rather than
only the last staging commits. See the [full comparison with v0.9.7](https://github.com/vaheed/CDNFoundry/compare/v0.9.7...v0.9.8).

The owner stopped the current job at this release checkpoint on 2026-09-20.
Phase 1 remains incomplete; this is not a claim of general production readiness.

## Domains, API and authorization

- Bind pending domain claims to fresh, claim-specific nameserver assignments and
  parent delegation, with expiration and retained claim evidence. Existing
  verified domains retain their delegation. Add public-suffix validation and
  PostgreSQL claim-concurrency qualification.
- Validate parent delegation using signed DNS fixtures and real authoritative
  checks, rather than accepting shared nameservers as fresh ownership evidence.
- Commit idempotency receipts atomically with their mutations. Commit edge task
  receipts with their aggregate outcomes to prevent split success/failure state.
- Recheck current authorization, domain lifecycle, record configuration and origin
  selection before queued origin probes run or their results are accepted.
- Keep domain-user browser workflows aligned with the same claim, origin and
  authorization rules used by the API.

## Edge identity, placement and origin handling

- Authenticate the exact enrolled edge certificate and explicitly issue client-only
  identities. Preserve trusted certificate provenance through edge-control ingress
  and clear that provenance header at ordinary web ingress.
- Restrict reports and artifacts to their owning edge, retain monotonic revisions,
  and remove configuration broadcast to edges without explicit placements.
- Require HTTPS control origins and reject redirects in the edge agent.
- Compare origin addresses by parsed value, enforce deny precedence, reject unsafe
  DNS answer sets, and retain correct native IPv6 peer formatting. Revalidate
  probe DNS and report actual TLS verification rather than assuming success.
- Bound complete A/AAAA answer validation, retries and connection reservations;
  release only acquired reservations, including after hostname removal, and account
  for the final upstream response correctly.
- Fix full-cache-purge serialization so cells receive an empty array when no URL
  keys apply. Normal reconciliation and fresh full purge now pass on staging.
- Include gateway candidate-rejection and generation-mismatch diagnostics carried
  forward from the changes already on `main` after v0.9.7.

## TLS lifecycle and certificate admission

- Validate uploaded chains, issuer constraints, cryptographic strength, names and
  expiry; persist canonical public chains and reject uploads validated against an
  obsolete domain revision.
- Serialize managed certificate planning, custom selection, activation, challenge
  cleanup and finalization under the relevant domain/order locks.
- Preserve terminal issuance outcomes on late failures or delayed finalization
  responses, and commit obsolete outcomes with their operation receipts.
- Keep renewal and forced-reissue receipts distinct and rotate bounded maintenance
  across eligible domains to avoid repeatedly selecting only the first group.

## Fleet and production operations

- Validate typed Fleet configuration and activate complete bundle generations.
  Preserve explicit address removals and existing identities during repeated setup.
- Protect PowerDNS credentials, make rotation retryable, and start edge services
  from the host's actual enrollment state rather than stale rendered assumptions.
- Correct staging DNS/preflight permissions and allow Fleet Prometheus to reach
  remote scrape targets while retaining private service networks.
- Expand production quick starts and operator references with the actual browser
  and API order for management DNS, claims, enrollment, pool readiness, origin
  activation, TLS and runtime acknowledgements.
- Add bounded Python checks for public health, observability, customer traffic,
  control-outage serving and PoP restart continuity. Browser qualification remains
  manual and owner-run.

## Dashboard and telemetry

- Add one administrator-controlled display timezone for both panels, preserving
  UTC storage, API timestamps and complete-hour aggregate query boundaries.
- Show healthy-edge counts independently of traffic availability and distinguish
  health-check time from traffic freshness.
- Exclude recovered same-domain nameserver-verification failures from active health
  and affected-domain counts while preserving failed-operation history. Pending
  retries, newer failures and independent backup warnings remain visible.
- Record actual origin latency and distinguish upstream failures from successful,
  redirect and client-error responses. Missing timings remain null.
- Attribute production events to enrolled edge identities for edge-filtered
  analytics; collectors without a host override preserve incoming identity.
- Retain the telemetry CSV date-range correction already on `main` after v0.9.7.

## Dependencies, publishing and qualification

- Expand the managed, digest-pinned release to 17 images. Gate publication on
  complete scans, keyless signatures, SPDX SBOMs and SLSA provenance for every
  release image and a signed manifest. Derive its migration marker from source.
- Rebuild or update Caddy, PostgreSQL helpers, Vector, Prometheus, Alertmanager,
  node exporter, PowerDNS, DNSdist, Loki and the edge runtime with pinned sources
  and patched dependencies; qualify relevant ingress, DNS, telemetry and database
  upgrade behavior. Update the selected ClickHouse LTS and Valkey images.
- Rebuild the Grafana backend and owner-approved ClickHouse plugin with patched
  dependencies. Preserve the documented, narrow Grafana/Tempo classifications,
  their expiry and raw scan evidence; this release does not broaden exceptions.
- Reuse cached parallel image builds, split DNS builds, bound disposable runner
  resource use, retry pinned fixture downloads and preserve tool failures in CI.
- Isolate Laravel tests from persistent development PostgreSQL and storage using
  guarded SQLite memory. Add real PostgreSQL, BIND, OpenResty, mTLS, origin and
  uploaded-certificate qualification, plus attributable evidence checks.
- Archive the legacy hardening roadmap unchanged and replace the active plan with
  bounded delivery and qualification jobs. Preserve the completed audit record
  and its outstanding acceptance gates rather than claiming a new full audit.

## Upgrade and deployment

Follow the [upgrade guide](../../deployment/upgrade.md), especially its September
security transition order. Upgrading a previous release requires more than the
latest staging-only image changes:

1. Preserve PostgreSQL, named volumes, keys, enrollment identities and previous
   image references. Select only a successful workflow's verified signed manifest.
2. Deploy the matching `web` and `edge-control` ingress changes before the new core
   so verified client-certificate provenance reaches authentication correctly.
3. Drain old nameserver-verification workers and pause new claims during transition.
   Apply `2026_09_05_160000_add_domain_delegation_claims` explicitly, then update
   core, Horizon and Scheduler together. Retain claim evidence; this migration
   deliberately refuses destructive rollback.
4. Apply `2026_09_20_170000_add_display_timezone_setting` explicitly. It seeds UTC
   without overwriting an existing preference. After deployment, use **Platform
   settings → Display → Display timezone** for the shared panel preference.
5. Verify explicit domain pool/cell assignments, identity rotation requirements,
   artifact acknowledgements and serving behavior through the documented canary
   procedure. Keep paired OpenResty configuration and Lua corrections together.
6. Validate and deploy the mounted Vector configuration. Production collectors
   receive `CDNF_TELEMETRY_EDGE_ID` from the enrolled `EDGE_ID`; retain buffer
   volumes and qualify new events. Historical telemetry is not rewritten.

## Qualification and remaining gates

Live staging passed control/DNS health, account isolation, HTTP origin with
verified visitor HTTPS, cache/URL/full purge, security deny/restore, Grafana API
checks, serving during control outage and recovery after a PoP Docker restart.
Focused automated results and exact deployed versions are recorded in the
[development handoff](../development-handoff.md).

At this checkpoint, the control/UI fixes and final Vector identity mapping are
committed but not deployed. Both owner login/access checks passed. Remaining
browser checks are not run, and the healthy-edge KPI needs a deployed retest after
its earlier failure. Verified HTTPS origin transport was not exercised; the owner
selected an HTTP origin with managed visitor TLS. The missing-backup warning is
intentionally retained, with backup setup deferred by the owner.

The next separate job is to finish the remaining [Phase 1 gates](../../roadmap.md).
Existing security gates and documented exceptions remain unchanged. Tag creation
starts publication; image publication is complete only after its required checks,
scans, signatures and attestations succeed.
