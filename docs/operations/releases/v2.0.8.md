# CDNFoundry v2.0.8

v2.0.8 closes the default exposure of internal listeners and the admin surfaces, delivers automatic security changes
without creating configuration revisions, and gives operators more to read: download and upload volume, a domain
history, and separate liveness facts for each edge. You can upgrade from v2.0.7 with Fleet. Three additive migrations
run during the upgrade: run `migrate` before restarting the web and Horizon containers.

## Added

- **Default-deny firewall.** Every Fleet bundle includes `firewall.sh`, which admits the fleet's own addresses to the
  internal listeners (exporters, DNSdist statistics, PowerDNS transfer) and drops everything else. Public listeners are
  not touched. Adding or removing a node refreshes the bundle on the other hosts.
- **Management networks.** Operators name the networks that may reach the admin panel and admin API, one entry at a
  time. Other networks receive 403. The customer panel, customer API, and status page stay open to everyone.
- **Strict Content-Security-Policy.** Responses carry a strict policy, and wildcard CORS origins are refused.
- **Security overlays.** Automatic security state reaches each cell as a sequence-guarded overlay, not as a
  configuration revision. A cell enforces the stricter of the snapshot and the overlay, and removing the overlay
  restores the snapshot.
- **Domain history.** A History tab lists operator and automatic events, with a filter for each. Each configuration
  revision carries a one-line summary of the sections that changed.
- **Download and upload volume.** Rollups by edge, cell, domain, and country appear in the API and the usage dashboard.
- **Edge liveness in two parts.** Edge screens show when control last heard from an edge and whether it serves.
- **More telemetry.** Gateway handshake failures are reported by reason, and ModSecurity verdicts and the raw request
  path are logged.
- **Health checks.** An alert pipeline with no receiver is a failed check in Fleet doctor and on the panel health page.
  A control install takes and verifies its first backup before it reports ready.
- **Analytics for all of a user's domains,** with range and domain filters.

## Changed

- A request that carries a cookie bypasses the cache unless the cookie name is ignored.
- Repeated query parameters keep the client's order in the cache key.
- Security events keep one record per domain, edge, reason, and hour. Old events and operations are pruned.

## Security

- The core image runs on PHP 8.5.12. `expose_php`, `display_errors`, and `session.upload_progress.enabled` are off, so
  no response carries `X-Powered-By` or an inline PHP error.
- Public listeners no longer name nginx or PowerDNS versions, and every core process runs as `www-data`.
- The OpenResty and production nginx images upgrade `libxslt` to 1.1.43-r4. The Go agent and gateway build on Go
  1.26.11.

## Fixed

- A ClientHello split across TLS records is reassembled, and gateway refusals are counted by reason.
- An invalid advisory heartbeat entry no longer rejects the heartbeat; liveness is recorded first.
- A published endpoint stays in DNS while its gateway takes a new revision.
- A domain's own protections no longer count toward an automatic security state change.
- Loki labels keep to a fixed set, and the admin overview fits phones.

## Upgrade notes

- Migrations `2026_11_12_000100`, `2026_11_12_000200`, and `2026_11_12_000300` add columns, indexes, and a constraint,
  and move existing suspected domains to the new automatic state, so mixed-version nodes keep working during a rolling
  upgrade.
- The management networks setting defaults to every network, so an upgrade does not lock anyone out. Narrow it after
  the upgrade.
- Rerun Fleet `start` on every host so the new `firewall.sh` is applied.
