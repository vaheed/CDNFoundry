# CDNFoundry v2.0.5

v2.0.5 fixes four reasons a new fleet did not answer DNS or show logs, and lets Fleet fill the DNS setup for you.
You can upgrade from v2.0.4 with Fleet.

## Fixed

- **DNS nodes never received zones.** `pdns-auth` could not reach the primary, so every transfer failed with
  `Network is unreachable` and the node answered `REFUSED`. It now joins the egress network. It still publishes no port.
- **Pair names with capital letters failed.** The platform DNS identity update was rolled back with
  `PowerDNS read-back did not match`. Customer nameserver pair names are now lowercased.
- **No logs after setup.** The monitoring presets left central logs off. They now turn Loki and the collectors on.
- **The Fleet gate hung.** It checked ports 80 and 443 on loopback. It now checks the public address, and passes while
  no pool address is placed on the PoP yet.

## Added

- After it installs the control node, Fleet registers the PowerDNS primary as a DNS cluster and stores the platform
  DNS identity (platform domain, `ns1` and `ns2` with IPv4 glue, standard SOA values). It never replaces existing values and
  sends no IPv6 glue.
- A failed installation in Fleet web shows **Retry the installation**.
- The DNS identity review lists every customer nameserver pair.

## Before you upgrade

Check out the `v2.0.5` tag, then open **Upgrade** in Fleet web or run `cdnfoundry-fleet upgrade --plan-only`.
Hosts installed with an earlier release keep their settings. For central logs, open **Config**, set **Central logs**
to **On** with the control host as the log host, and deploy. If a pair name already contains capitals, change it to
lowercase before you save the identity again.
