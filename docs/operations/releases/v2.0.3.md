# CDNFoundry v2.0.3

v2.0.3 fixes problems found by installing, changing, failing over, and removing a real fleet with the Fleet
CLI and Fleet web. It also fixes a fresh-volume ClickHouse start. You can upgrade from v2.0.2 with Fleet.

## What changed

- **Set monitoring, central logs, and backups in Fleet web.** The **Config** page now has the same three
  settings as the CLI commands `configure-monitoring`, `configure-logs`, and `configure-backups`.
- **Add a standby as a non-root user from Fleet web.** The HA form asks for the SSH user.
- **A step-by-step HA guide.** [Set up control-plane HA step by step](../set-up-control-plane-ha.md) covers
  both a local network and a WireGuard tunnel, with checks after each step, a practice switchover, and
  removal.
- **Dedicated monitoring is explained.** [Production fleet reference](../../deployment/production-fleet.md)
  now lists what a monitoring host needs, including a private route to the control database.

## Fixed

- **`apply-config` missed changes.** Fleet compared a new render with the previous render, so a setting
  saved by one command and rendered by the next was reported as "unchanged" and never reached the hosts.
  It now compares each bundle with what that host last ran successfully.
- **A standby that could not be promoted.** `control add-standby` crashed with `KeyError` on some setups,
  and a standby added without the release image pins failed to start when promoted with
  `Mutable bundle image rejected`. New standbys get the same digest-pinned images as the active node.
- **ClickHouse did not finish its first start.** Its init script could not stop its temporary server. The
  container now keeps the one capability it needs (`KILL`).
- **A failed image pull crashed Fleet with a traceback**, and its message hid the reason. It now names
  the image and what Docker said, for example a DNS or registry error.
- **Finished one-shot containers showed a host as degraded.** A container that exited with code 0 is
  done, not down.
- **A monitoring-role node with colocated monitoring** rendered a bundle that failed validation on the
  host. Fleet now refuses it and says which setting to change.
- **Fleet web errors** showed raw Python text such as `'role'`. They now say which field is missing or
  that a number is expected, and form fields no longer overflow a phone screen.

## Before you upgrade

Check out the `v2.0.3` tag, then open **Upgrade** in Fleet web or run
`cdnfoundry-fleet upgrade --plan-only`. Take a backup first. The ClickHouse capability takes effect
when the telemetry stack next starts.

## Limits

`remove-node` removes a host from the plan only. Stop its services and delete its data yourself, as
described in [Fleet engine, vault, and local web](../fleet-engine.md#removing-a-node). Dedicated
monitoring still needs a PostgreSQL endpoint the monitoring host can reach over a private network.
