# CDNFoundry v2.1.1

v2.1.1 fixes an upgrade from v2.0.8 that stopped in `clickhouse-migrate`. You can upgrade from v2.0.8 or v2.1.0 with
Fleet. No control-plane migration is added; one ClickHouse migration is renamed.

## Fixed

- **Upgrade from v2.0.8 stopped at the telemetry migration.** The rollup view `security_hourly_mv` reads
  `edge_events.security_rule`, but the migration that adds that column ran after it, so `clickhouse-migrate` failed with
  `UNKNOWN_IDENTIFIER` on a database created by v2.0.8 or earlier. The column migration now runs first. It is idempotent,
  so hosts that already applied it simply apply it once more.

## Upgrade notes

- If an upgrade to v2.1.0 already stopped at `clickhouse-migrate`, upgrade to v2.1.1 and rerun Fleet `start` on the
  control host. Nothing was recorded for the failed migration, so it runs cleanly.
- Run `clickhouse-migrate` before restarting the web, Horizon, and cell containers, as in v2.1.0.
- **Administrator panel answers `Forbidden`.** Since v2.1.0 the management-network check judges the real client address
  instead of the proxy hop. When `MANAGEMENT_NETWORKS` is set, `/admin`, `/api/admin`, and Horizon answer a bare 403 to any
  client outside it. Add your address to `MANAGEMENT_NETWORKS` in the Fleet configuration, and keep `TRUSTED_PROXIES`
  covering the proxy in front of the control plane. The customer panel at `/app` is not restricted.
