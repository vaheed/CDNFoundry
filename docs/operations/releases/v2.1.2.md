# CDNFoundry v2.1.2

v2.1.2 limits a domain whose nameservers are not verified to its DNS records, and stops usage and delivery history from
growing without bound. You can upgrade from v2.1.0 or v2.1.1 with Fleet. One control-plane migration adds the retention
settings, the `month` usage granularity, and supporting indexes; one ClickHouse migration backfills `security_hourly`.

## Added

- **Usage compaction.** `cdnf:usage:compact` sums hourly usage into daily rows after 35 days and daily rows into monthly
  rows after a year, with the same totals.
- **History pruning.** `cdnf:history:prune`, `queue:prune-failed`, and `sanctum:prune-expired` run daily and remove
  finished edge tasks, cache purges, certificate orders, expired name holds, old failed jobs, and expired tokens. New
  retention settings control the windows.

## Fixed

- **Unverified domains.** Until nameservers are verified, only DNS records can be managed: the WAF, security, cache, TLS,
  proxy, analytics, and log pages are hidden, the API answers them with `409 domain_not_verified`, and Geo-DNS and
  proxied records are refused.
- **False DNS drift.** A deleted domain's pending zone retirement no longer degrades Authoritative DNS.
- **Fleet backups.** The Fleet web Backups form saves the S3 access key ID and secret into the vault.
- **Analytics.** Attack score, action, country, and network breakdowns include events stored before the rollup existed;
  table headings and client addresses are no longer cut off.
- **Panel.** Next works on the Security events list, and the DNS identity "Add" buttons read correctly.

## Upgrade notes

- Run `clickhouse-migrate` before restarting the web, Horizon, and cell containers.
- Existing domains that are not verified lose access to non-DNS pages until verified.
