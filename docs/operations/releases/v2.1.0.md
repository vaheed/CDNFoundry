# CDNFoundry v2.1.0

v2.1.0 gives domain users their own protections and ways to be told about problems: notification channels, log push, a
time-limited incident profile, and a typed rule engine with rate limits, managed-WAF tuning, and application
protections. Administrators can apply platform rulesets and log in as a domain user to help. You can upgrade from
v2.0.8 with Fleet. Fourteen additive control-plane migrations and four ClickHouse migrations run during the upgrade:
run `migrate` and `clickhouse-migrate` before restarting the web, Horizon, and cell containers.

## Added

- **Notifications.** One `notifier` container delivers alerts and domain events to Telegram, Discord, Slack, and an
  administrator-only signed webhook, with per-channel rate limits, digests, and automatic pausing after repeated failures.
- **Log push.** A domain user can send their own HTTP requests, security events, and DNS queries to an HTTPS endpoint or
  S3-compatible storage, when an administrator allows it. One shared `log-pusher` worker serves every domain.
- **Incident profile.** One time-limited bundle of protections for a domain that expires on its own and is enforced by
  every cell, including a proof-of-work challenge.
- **Typed security rules.** Conditions on request fields, five actions, presets, preview and reorder endpoints, and
  per-cell fixed-window rate limits.
- **Managed WAF tuning.** An attack score on every request, attack-score rule fields, and per-domain adjustments to the
  managed rules.
- **Platform rulesets** that administrators apply to all domains or a chosen list.
- **Security events and analytics,** with the rule behind each mitigated request and an alert when a threshold is reached.
- **Application protections.** Leaked-password check, sensitive-data logging, AI-prompt scoring, API schema checks, and
  report-only CSP with client-side script reports.
- **Cache path rules** and cookie name prefixes in the domain cache policy.
- **Domain dashboard.** Traffic, what needs action, and every domain, in the domain panel.
- **Log in as.** An administrator can act as a domain user; the session is marked and audited.

## Changed

- Notification channels replace the single alert webhook.

## Removed

- `ALERT_WEBHOOK_URL`, the Fleet `alert-webhook` command, and the Fleet web alert webhook field. Add notification channels
  in the panel before you upgrade if you relied on the webhook.

## Security

- Laravel framework 13.42 clears the task output injection advisory.

## Fixed

- A signed-in administrator who opens `/app` is sent to `/admin` instead of a 403 page.

## Upgrade notes

- Run `migrate` and `clickhouse-migrate` before restarting. All control-plane migrations add columns or tables, and the
  rule migration converts existing security rules to typed conditions, so mixed-version nodes keep working during a
  rolling upgrade.
- Remove `ALERT_WEBHOOK_URL` from your Fleet configuration. Fleet refuses the old field.
- Rerun Fleet `start` on the control host so the `notifier` and `log-pusher` containers start.
