# CDNFoundry v2.1.5

v2.1.5 fixes browser verification on domains with restrictive HTTP method policies. It also adds signed IPFire location
updates and administrator removal of disabled, drained edges.

## Browser verification

A domain that permitted only `GET` could show **Checking your browser**, then reject the browser's verification request
with `405 Not Allowed`. This also affected Under Attack mode.

When a challenge is active, `POST /.cdnf/challenge` now passes domain and incident method restrictions. Proof validation,
body limits, client containment, and firewall rules still apply. Ordinary requests keep their configured method restrictions.
There is no change to proof difficulty, token lifetime, client binding, or replay protection. See
[incident response](../../guides/incident-response.md).

## Location data and edge administration

- Fleet uses signed IPFire location data by default, refreshing country and ASN databases daily. Custom MMDB sources remain
  supported. Failed verification retains the previous valid data.
- Cells reopen GeoIP handles after database replacement without restarting. The updater uses the patched Alpine runtime.
- Administrators can remove an edge after disabling and draining it. Assigned edges remain protected. Removal records an
  audit event and queues platform DNS reconciliation. See [edges](../../guides/edges.md).
- The README and documentation homepage include project sponsorship links.

## Upgrade and rollback

Deploy through Fleet using a signed release manifest with digest-pinned images. Upgrade the affected control, edge, and
MMDB updater images through a release; do not copy runtime files directly into running cells. Refresh the checkout used by
Fleet so its default location-source configuration matches this release.

There are no new database migrations since v2.1.4. Earlier releases must still follow their migration requirements in the
[upgrade guide](../../deployment/upgrade.md). Existing desired state, named volumes, keys, and certificates must be preserved.

Rollback through Fleet to the previous signed release. The previous runtime restores the GET-only challenge defect.
Edge removal is an explicit deletion; rolling back software does not recreate an edge that an administrator removed.

## Qualification

The release qualification record covers disposable local runtime containers, the seeded browser stack, and isolated backend
tests. Public staging diagnostics reproduced the reported verification request returning 405 and confirmed the domain's
GET-only method policy. These diagnostics did not deploy the fix or change the staging policy.

Checks executed for this release:

| Check | Result |
| --- | --- |
| Browser challenge runtime | Passed: restrictive domain and incident methods, IPv4/IPv6 binding, replay and oversized-proof rejection |
| Signed IPFire updater runtime | Passed: native signature, deterministic updates, rollback and tamper rejection, first-start recovery |
| ASN and live GeoIP reload runtime | Passed: IPv4/IPv6 lookups, update and outage retention, reader replacement |
| Edge removal backend | 5 tests passed, 23 assertions |
| Edge removal browser spec | 4 passed: light/dark desktop and phone, visual snapshots and accessibility |
| Go tests and vet | Passed for the agent, gateway, and location compiler |
| PHP formatting and static analysis | Passed; PHPStan baseline unchanged |
| Version, OpenAPI, supply-chain policy, and Compose checks | Passed |
| Documentation | Passed: build, generated references, and internal links |

The browser run was limited to the edge removal spec. The full panel and Fleet browser suites and full development runtime
suite were not rerun for this patch. The configuration test used in-memory SQLite; development database volumes were preserved.

The [production qualification requirements](../production-qualification.md) still apply to each operator's fleet.
This patch does not close the existing multi-PoP WAF staging gate, or claim a new fleet failover, backup/restore, or
production load qualification. Tag CI builds and scans the release images before publishing the GitHub release.
