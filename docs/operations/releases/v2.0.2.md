# CDNFoundry v2.0.2

v2.0.2 makes long Fleet actions visible and faster, and fixes an install that hung at
ClickHouse migration. It does not change the DNS or edge runtime. You can upgrade from
v2.0.1 with Fleet.

## What changed

- **A live action page.** Every step of an install, upgrade, or check is listed up front,
  grouped by host, and ticked as it finishes, with a progress bar and a log that follows
  the end. **Stop after this step** stops cleanly between steps. If you leave the page,
  every page shows the running action, and an interrupted install offers **Continue**.
- **What a host prints, while it prints it.** Starting a host runs migrations and waits for
  health checks. Fleet now shows each line as it appears and says when a step has been
  quiet for 30 seconds.
- **Hosts prepare together.** Fleet connects to every host, installs prerequisites, and
  pulls images on all of them at once before it installs the first, instead of one host
  after another.
- **Inventory and a live view.** Processor, memory, disks, kernel, Docker, time sync, and
  containers of every host, with findings, a state for each host that refreshes on its
  own, container log tails, and the commands `inventory` and `watch`.
- **The alert webhook is optional.** With no `ALERT_WEBHOOK_URL`, Alertmanager starts with
  receivers that send nothing, so you can install first and add a notifier later. Set it on
  Deploy or Config, or with `cdnfoundry-fleet alert-webhook`, then deploy the configuration.

## Fixed

- An install could hang at ClickHouse migration for as long as the Fleet session stayed
  open. Host commands now get an empty standard input.
- Pinning several hosts at once could lose host keys.

## Before you upgrade

Check out the `v2.0.2` tag, then open **Upgrade** in Fleet web or run
`cdnfoundry-fleet upgrade --plan-only`. Take a backup first. The Alertmanager change
takes effect on each host with the next configuration deploy.

## Limits

Fleet keeps the live readings in memory only. Closing Fleet web discards them; the last
**Read hardware** result stays in the vault. If the Fleet web process is stopped in the
middle of an install, nothing is saved for **Continue**, so start the install again; every
step is safe to repeat.
