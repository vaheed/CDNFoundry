# CDNFoundry v2.0.7

v2.0.7 stops edges from advertising their software, removes false "degraded" alarms, and fills the admin overview and
telemetry pages with real detail. You can upgrade from v2.0.6 with Fleet. Two additive database migrations run during
the upgrade: run `migrate` before restarting the web and Horizon containers.

## Added

- **Hide edge diagnostic headers.** The platform setting `proxy_defaults.diagnostic_response_headers` (off by default)
  controls `Server`, `X-CDNF-Cache`, `X-CDNF-Origin`, `X-CDNF-Origin-Transition`, `X-CDNF-Error`, and
  `X-CDNF-Security-Reason` on proxied responses. Turn it on while debugging cache or origin failover. The `Server`
  header never carries a version. Telemetry is unaffected.
- **Acknowledge failed operations.** An administrator can acknowledge a failure from Operations (row, bulk, or
  "Acknowledge all failures") or with `POST /api/admin/operations/{operation}/acknowledge`. The record and its error
  stay and the audit log records who acknowledged it. A later successful operation of the same type for the same
  domain also resolves a failure. Retrying clears an acknowledgement.
- **A fuller overview.** The admin overview adds a platform inventory (domains, proxied hostnames, certificates,
  ready cells, WAF coverage, release), the traffic and error charts, edge health, cache and DNS panels, queue lanes,
  and data freshness.
- **Telemetry drill-down tables.** Every link from the overview opens detail tables for traffic, cache, origin, or DNS
  instead of the same page.

## Fixed

- **Managed WAF could not be enabled on a pool.** The form required a release field the operator could not fill. It is
  now set from the pinned image when the toggle is switched on.
- **Charts trailed real time.** Charts and totals ended at the last complete hour. The hour in progress is now charted
  and labelled "so far".
- **The failed-operations tile and `cdnfoundry_operations_failed_recent` counted recovered failures.** They now count
  only unresolved ones.
- **The Global traffic and Global DNS tables scrolled sideways.** They now fit their panel.

## Changed

- Timestamps no longer print the timezone name or offset. The platform timezone setting defines the zone.

## Upgrade notes

- Migrations `2026_11_10_000200` and `2026_11_10_000300` only add a setting key and nullable columns, so mixed-version
  nodes keep working during a rolling upgrade.
- Edges receive the new header behavior with the next signed domain revision. Changing the setting queues a global edge
  reconciliation.
