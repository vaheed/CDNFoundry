# CDNFoundry v2.0.0

v2.0.0 is a **breaking release**. It has no backward compatibility with 1.x and no
data migration. Deploy it from scratch with the
[production guide](../../deployment/production-guide.md).

## Highlights

- **Safer by default.** Private keys no longer travel in snapshots or artifacts.
  An agent fetches a key over mutual TLS, encrypted to that edge. API responses use
  explicit resources, and tokens have expiries, abilities, and optional per-domain
  scope. Administrators can use two-step sign-in.
- **A control-plane fault no longer becomes an outage.** A PoP leaves DNS only on a
  positive signal, never on missing heartbeats. Pools keep their last published
  set, PoPs probe each other, edge identities renew over mutual TLS, and one bad
  artifact only rejects the domain it belongs to.
- **Hidden-primary DNS.** Laravel writes to one private PowerDNS primary. DNS
  nodes are secondaries that pull zones with signed transfers.
- **Production readiness.** IPv6 for DNS, control, and edges, encrypted backups,
  and an explicit supply-chain policy.
- **Optional control-plane high availability.** Add a warm standby control node
  with a fenced epoch, a planned switchover, and clear failure behavior. A single
  node stays supported.
- **A new admin and domain UI.** Both panels use one design system, in light and
  dark mode, with agent-run browser qualification.
- **Fleet over SSH, and a local Fleet web.** Install, upgrade, back up, and roll
  back hosts from the command line or a web page on your workstation, using signed
  release manifests.
- **Observability.** Role-based Grafana with 35 dashboards in 8 folders, 77
  alerts with runbooks, probes, and usage and operations reports.
- **Documentation rebuilt.** Six sections, task-first pages, a glossary, a FAQ,
  an alert reference, a Grafana reference, and a generated Fleet CLI reference.

## Breaking changes

- **No upgrade from 1.x.** Rebuild from scratch. There is no data migration.
- **New database baseline.** Migrations are squashed into one PostgreSQL and one
  SQLite baseline, followed by later migrations.
- **Edge agent:** `EDGE_RUNTIME_DIR` is required. There is one activation path.
- **DNS:** the platform zone goes to the hidden primary. The column
  `platform_dns_settings.cluster_targets` is removed, and DNS hosts no longer need
  an API gateway.
- **Environment:** every documented tunable is now passed to the control plane
  through `.env.prod`. `EDGE_PROXY_SECRET` and `METRICS_TOKEN` are no longer read
  from the environment. Use their `_FILE` forms.
- **Cells:** each edge host has eight cell slots, fixed.
- **Tests and tooling:** the end-to-end suites and Make targets are named after the
  feature they test.

## What was qualified

CI runs the Laravel suite, Go tests, the Fleet tests, Compose and supply-chain
policy checks, the OpenAPI contract, the documentation build and its link and
command checks, and non-UI Python real-runtime qualification against real
PostgreSQL, PowerDNS, DNSdist, OpenResty, Vector, and ClickHouse. The browser suites
cover both panels, the Fleet web, and Grafana, against seeded development stacks.

## Know before you deploy

- **Qualify on your hardware.** As for any infrastructure, run the
  [production qualification](../production-qualification.md) before you send
  customer traffic.
- **Sizing.** There are no published throughput numbers. Measure your own
  hardware with the [sizing guide](../../deployment/sizing.md).
- **Not a DDoS scrubber.** CDNFoundry limits requests per client, domain, and cell.
  It does not remove traffic that fills your uplink.
- **No private origins.** Origins must resolve to allowed public addresses.

## Report bugs

Use CDNFoundry in production and tell us what you find. Open an
