# CDNFoundry v2.0.4

v2.0.4 fixes edge enrolment on fleets whose edge identity CA was generated without a Subject Key
Identifier, and makes a failed host start show why. You can upgrade from v2.0.3 with Fleet.

## Fixed

- **Edges could not enrol.** Every edge agent stopped with `422 Unable to sign the edge identity
  certificate` and then, after repeated attempts, `429 Too Many Attempts`. Core required the CA certificate
  to carry a Subject Key Identifier, and the CA that Fleet generated did not always have one, depending on
  the OpenSSL build on the Fleet machine. Core now signs with either kind of CA, and Fleet adds the
  identifier to every new CA. You do not need to regenerate an existing CA.
- **Signing errors were hidden.** Core now reports an unreadable CA key, a key that does not match its
  certificate, or the OpenSSL error, and writes the detail to its log.

## Added

- **Failing containers explain themselves.** When a host fails to start, the Fleet action shows the last
  log lines of each container that is unhealthy, restarting, or exited with an error.

## Before you upgrade

Check out the `v2.0.4` tag, then open **Upgrade** in Fleet web or run `cdnfoundry-fleet upgrade --plan-only`.
Edges that stopped on the signing error enrol on their next retry once control runs v2.0.4. The `429`
clears when its rate-limit window ends.
