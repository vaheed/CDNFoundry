# CDNFoundry v2.1.3

v2.1.3 closes several gaps in the edge cell's security runtime and fixes a few panel and backup problems. You can upgrade
from any 2.1.x release with Fleet. There are no database migrations.

## Security

- **Managed WAF.** A request body without a `Content-Length` header (chunked or HTTP/2) is now read and scored. Oversized,
  unreadable, and compressed bodies are refused on a blocking level, and a failed scoring step falls back to inline
  inspection.
- **Rate limits.** Each domain has its own entry budget inside the cell's rate-limit dictionaries, so one domain's flood of
  client keys cannot evict another domain's counters or active blocks. Both dictionaries grow from 16 MB to 32 MB per cell.
- **IPv6.** A cell counts an IPv6 client under its prefix (64 bits by default; `EDGE_IPV6_RATE_PREFIX`,
  `EDGE_IPV6_EXACT_CIDRS`), matching the gateway.
- **Escalation.** A domain's automatic security state tightens only on evidence from several clients. One client that
  causes 20 escalating events in a minute is banned on that cell for five minutes.

## Fixed

- Security events from busy cells are reported fairly across domains, and the control plane counts the excess instead of
  failing the heartbeat.
- The browser challenge keeps a visitor's token across address changes inside an IPv6 prefix and browser updates;
  `EDGE_CHALLENGE_BITS` sets the difficulty (12 to 24, default 16).
- The admin edge page shows open client connections and gateway connections served.
- **Back up now** initialises a missing restic repository on a fresh S3 bucket.
- The Traffic, Cache, and DNS analytics focuses query ClickHouse correctly, and the admin Telemetry tables no longer cut
  off numbers and headings.

## Added

- The admin Customers list has an Owner column and a nameserver verification filter; admin domain pickers list verified
  domains only.

## Upgrade notes

- Restart the cells so they load the larger dictionaries and the new runtime.
